# SAE Guardrails

Online topic guardrails for LLM generations, built on sparse autoencoders.

An enterprise chatbot ships with a promise: a billing assistant answers billing questions, a
clinical assistant stays inside clinical territory. That promise is hard to keep because nothing in
a normal deployment watches where a response is going until the response is already finished — and
in a streaming product the user has usually seen the off-topic text before any filter runs.

This project watches the response *while it is being written* and names the topic of each token as
the model decodes. The output is a per-token topic label you can monitor and act on, so an
off-topic stretch gets caught while it is forming instead of after it is done.

The idea in one line: **we don't read the words the model writes — we read the model's own internal
features.** A synthetic corpus of topic-labelled conversations is generated by a strong teacher
model, a small deployment model reads each conversation and its hidden states are pushed through
per-layer sparse autoencoders into a sparse feature vector for every token, and a small **causal**
classifier turns those features into a topic label at each position. Because the classifier is
strictly causal — every prediction depends only on the current token and earlier ones — a model
trained in one parallel prefill pass stays valid at live decode time.

The seven topic domains are enterprise documents, general news & content, customer service, legal,
financial, HR & people operations, and healthcare. A record either stays on a single topic
(negatives that teach the detector not to invent a switch) or crosses one clean boundary into a
second topic.

A longer research write-up of the motivation and method lives in [`blog_online/`](blog_online/).

## Repository layout

The codebase has two maintained halves: generating the data, and training the classifiers on top of
the extracted features.

### `dataset/` — topic-axis dataset generation

Generates the synthetic, topic-labelled corpus using [Simula](https://github.com/Mercity-AI/Simula),
our data-generation engine. The core move is to treat the **topic label as the one controlled
variable** and let persona, tone, and task vary freely, so the label can never leak in through some
other axis.

- `build_topic_axis_taxonomy.py` — hand-authors the balanced taxonomy and sampling strategy, then
  audits it for free over tens of thousands of sampled configurations before any paid generation.
  Uniform primary/second-topic weights make every domain equally frequent and all ordered topic
  pairs reachable; hard `never_combine` rules forbid single-topic records with a boundary and
  same-topic pivots.
- `prefill_mvp_topic_axis.yaml` — defines the dataset, generation providers, and the strict
  structural validation rules for the teacher and reviewer models.
- `prefill_mvp_topic_axis_prompts.py` — builds the generation and critique prompts. The YAML refers
  to this module by filename, so the two files must stay together.

### `modeling/` — feature extraction and causal classifiers

Trains and evaluates the per-token topic classifiers on the extracted sparse-autoencoder features.
Each teacher-written exchange is read by the small model in a single causal prefill pass, residual
activations from the final layers are encoded by per-layer SAEs, and the top features per layer are
concatenated into one feature vector per token. That feature cache is built once and reused by every
experiment.

- `models.py` — every causal architecture: gated recurrent baseline, causal Transformer, and the
  temporal-convolution family (plain, gated, multi-scale, ConvNeXt), plus the joint
  topic-and-boundary variants. Causal convolutions trim right-padding so a token never sees the
  future; the Transformer uses a strict upper-triangular mask; normalization is per-token only.
- `train_gru.py`, `train_transformer.py`, `train_tcn.py` — the three architecture entry points.
  Each runs only its own architecture family, so mixed config files are safe.
- `training.py`, `training_joint.py` — shared training engines (not command-line entry points) that
  hold the checkpoint and metric logic the public scripts reuse.
- `decoder_utils.py` — the shared per-token sequence decoders. `raw`, `minimum_duration`,
  `hysteresis`, and `transition_penalty` are strictly causal; sticky Viterbi is retained for offline
  analysis only and is rejected by the causal training/evaluation path.
- `utils.py` — feature-cache validation/loading, the canonical deterministic response-level split,
  prediction, and metrics.
- `load_checkpoints.py` — restores ordinary and joint checkpoints without changing their saved
  format.
- `configs/` — the experiment configurations. Every completed run also saves its resolved config
  beside its best and final checkpoints.
